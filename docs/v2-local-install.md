# 真才实鉴 V2：他人电脑独立安装

本轮交付是 **Windows x64 本地版**：每位使用方在自己的电脑安装，千问办公作为使用入口，面试页面在同一台电脑的浏览器中打开。无需自建服务器；本轮不包含局域网、异地学生链接或公网发布。

## 收到交付包后

1. 将 ZIP **完整解压**到当前账户可写的固定目录，在千问办公中选择该目录。发送：**“请读取当前项目的 QWEN_HANDOFF.md，完成真才实鉴初始化并打开 HR 总控。百炼密钥由我在本机密码框输入。”**
2. 按千问显示的本机执行授权操作；需要密钥时，在弹出的密码框里输入自己的百炼 API Key。初始化完成后自动请求打开 HR 总控。

其余步骤由固定脚本完成：准备 Python、独立环境、固定依赖、模型、媒体工具和本机检查。缺少兼容 Python 时，会下载固定版本的官方安装器，并核对 SHA-256 和 Python Software Foundation 数字签名，安装到项目的 `.runtime/python312`，不修改系统 PATH。已有兼容环境直接复用。首次下载需要网络，声音模型约 1.12 GB，可能耗时较长。

如果千问没有主机执行权限或无法显示密码框，只需双击根目录的 **开始使用真才实鉴.cmd**，走同一流程。不要直接在压缩包中运行，不要放在 `Program Files`，不要复制开发机的 `.venv-suit`。整个过程不需要用户先导入 Skill 或粘贴 MCP JSON。

密钥和费用由使用者自己的百炼账户承担。模型固定为 `qwen3.7-plus` 和 `qwen3-asr-flash`，无需另选模型。账号与地域要求见[百炼配置说明](bailian-user-setup.md)。密钥由本机 Windows 账户加密保存，不发送到聊天、Skill 或导入配置。

千问若实际提供连接器管理工具，可以根据安装器生成的配置自动添加并检查连接；没有这项能力时，先交付 HR 页面即可。Skill 可后置导入，导入成功与工具调用结果分别验证，不能把生成配置文件当成已完成宿主安装。

## 日常使用

在千问调用真才实鉴 → 打开总控 → 新建批次 → 导入本机 DOCX 简历 → 为候选人建立面试 → 在同一台电脑的学生页面完成设备测试、自我介绍和 5＋3 题 → HR 查看个人 HTML、细则及批次排序 → 导出 HTML。

交付包从空数据开始，不包含开发机的 30 份简历、已有面试、录音录像、报告或授权链接。使用方可导入自己的多份 DOCX；30 人是演示批次规模，不是必须随包预装的人数。没有配套模拟简历时，不应显示一个无法使用的“导入 30 人”入口。

日常让千问在项目中打开总控，或双击“启动面试工作台.cmd”。已接入 MCP 时也可直接调用 `v2_open_workbench`；它启动或复用同一套本机服务。老师在千问看到的分数、个人 HTML 和同期 HTML 应来源一致。

## 文件与计算在哪里

| 内容 | 位置或处理方式 |
|---|---|
| 程序与题库 | 当前解压目录；原始评分工作簿不是运行时前置文件 |
| Python 依赖 | 当前目录的 `.venv-suit` |
| 辅助工具与运行依赖 | 当前目录的 `.runtime` |
| 下载的模型 | `suit-demo/models` |
| 人员、作答、录像、分析结果 | `suit-demo/local-data/v2` |
| 导出报告 | `suit-demo/local-data/v2/exports` |
| 本机加密百炼配置 | `suit-demo/.secrets-user`；不随包共享 |
| 千问导入资料 | `delivery/qwenwork-v2`；按当前电脑的实际路径生成 |
| 面部 AU、点位和声音情绪分析 | 本机运行，不上传视频进行这些计算 |
| Qwen 内容评分、百炼语音转写 | 使用自己的云 API 配置；发送对应评分文本或需转写的音轨 |

这是本地安装版，不是完全离线版。首次安装要下载依赖和模型；使用百炼能力时仍需网络和账户额度。千问办公账户与百炼 API 凭据分别配置。

## 重试与移动目录

安装失败时保留错误信息，解决网络或缺失前置条件后重新运行安装入口。已通过校验的模型应复用，下载不完整或哈希不符不能被当作成功。安装器不得删除人员数据、复制开发机凭据或替用户填写 API Key。

若自检提示 OpenFace 无法启动，按提示安装 Microsoft Visual C++ 2015–2022 x64 运行库后重试。自检区分“运行文件就绪”“百炼尚未验证”和“千问尚未导入”，不会用一个服务健康状态替代全部检查。

需要单独检查时，在项目根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install-v2.ps1 -Mode Doctor`；只查看安装计划可将 `Doctor` 改为 `Plan`。正常安装的检查结果保存到 `.runtime/install-v2-report.json`。整个初始化流程的只读计划为 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/first-run-v2.ps1 -Plan`。可单独运行 `.venv-suit\Scripts\python.exe scripts\prepare_qwenwork_v2.py` 重新生成可选的千问导入资料。

安装完成后尽量保持目录不变。若移动目录或更换电脑，需要重新准备环境并重新生成、导入该电脑的 MCP 配置；旧 `.venv-suit` 与 Windows 加密密钥不作为可移植文件复制。新版本的源码包也不是人员数据备份，V1 数据迁移脚本不能用于 V2 数据库。

## 验收边界

交付检查包括安装计划和失败分支、配置生成、MCP 启动协议、以及将源码包解压到另一条含中文和空格的路径后，用合成简历走完批次、5＋3 题、个人/同期 HTML 和导出。

这些检查不替代另一台干净 Windows 电脑的首次下载、模型推理、摄像头/麦克风授权及千问桌面端真实导入验收。已具备环境的本机通过检查时，应明确写“本机验证通过”，不能标为“其他电脑已验证”。

第三方程序和模型继续保留来源及许可，适用范围见根目录 `NOTICE.md` 和各模型随附说明。
